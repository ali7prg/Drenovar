3. BUILD ROUTES AND UNAVAILABLE REQUIREMENTS

tools/package-ios.sh imports with godot --headless --path project --editor --import, then exports the iOS preset to an output DRENOVAR.ipa path while export_project_only=true. It requires the resulting DRENOVAR.xcodeproj/project.pbxproj and DRENOVAR.pck. On non-Darwin it prints that a macOS host is required and exits successfully with exported project/resources only. On macOS it calls xcodebuild Release/iphoneos/arm64, derived data in the output directory, CODE_SIGNING_ALLOWED=NO, CODE_SIGNING_REQUIRED=NO, DEVELOPMENT_TEAM empty. It then packages Payload/DRENOVAR.app into DRENOVAR-unsigned.ipa and verifies ZIP integrity.

tools/ios-template.py pins VERSION=4.6.3. It reads templates/ios.zip from the official template archive URL recorded in that script. It requires curl with byte-range support and validates Content-Range plus exact returned length. It does not bundle the template in this archive.

tools/repack-tested-engine.py takes previous.ipa new.pck output.ipa, preserves the engine executable/framework bytes, replaces DRENOVAR.pck, writes CFBundleShortVersionString=0.5.9 and CFBundleVersion=19, excludes _CodeSignature and embedded.mobileprovision, verifies a native Mach-O header, ZIP CRC, executable SHA-256 equality and PCK SHA-256 equality. This is package repacking, not an Xcode compilation or signing. It needs a prior compatible IPA, which is not in this source ZIP.

.github/workflows/drenovar-ios.yml targets branch native-ios-godot and changes under native-ios/**. It assumes a repository containing this package at native-ios, uses macos-15, Node24, downloads Godot4.6.3 and its iOS template, fetches/imports assets, and builds an unsigned arm64 IPA. Artifact retention is five days. Copying the ZIP root unchanged to a different repository layout does not match that workflow's working-directory without deliberate adaptation.

Apple team identification, provisioning profile, signing certificate/private key, Xcode installation, export templates and a physical iPhone are external dependencies. No signing identity can be inferred from the placeholder 0000000000. No App Store/TestFlight release receipt is included.

Historical records CHANGES0.5.2–0.5.9 consistently say that test IPA needs signing; 0.5.2 explicitly says a normal open-file operation does not directly install it. Recent iterations reused the existing native Godot4.6.3 binary with a new PCK. Physical iPhone12 Metal, input latency, sustained FPS, memory and heat acceptance remain open. There are no Xcode build failure logs or evidence in this ZIP that would support inventing a specific export crash and its fix. Distinguish runtime complaints from export errors.

6. CRITICAL REPRODUCTION / DOCUMENTATION GAPS

.gitignore excludes /project/assets/ entirely, also /project/.godot/ and /build/. The source ZIP nevertheless contains the asset files. A plain new Git commit that obeys this ignore rule can omit all assets. Preserve and transfer the supplied full asset tree; do not mistake the repository alone for this full archive.

CI rebuilds assets using tools/web84-sources.json (248 pinned web files) from live production URL paths. fetch-web84-assets.mjs requires their SHA-256 to match pinned bytes and will fail if a referenced current server file has changed. This preserves integrity but leaves reproduction dependent on the old inputs remaining available. Names web84/web-v90 do not prove latest backend version; README/changes use references90,91 and92 in different sections.

The importer does NOT create or copy the later assets/ui/resources.png, assets/ui/actions/*.svg, assets/ui/web-panels portraits, assets/intro/keep-wide.png, NotoSerif font or its license. Thus a clean Git checkout with ignored assets and the current fetch/import workflow cannot be assumed to reproduce the complete0.5.9 archive. This is a concrete packaging gap; audit did not change the workflow. Keep bundled assets authoritative and address pipeline coverage deliberately in subsequent development.

asset-integrity.json is stale: baseline0.5.4, version0.5.5, matching_original_assets718. It is a summary count, not a full current file hash manifest. Do not present718 as the current total. original-assets.json is accurate for its203 entries but not a complete inventory of732 source asset files.

README's general “Текущий объём” still says native session lives only in RAM and scene reuse is4seconds. Current code/CHANGES say encrypted persistent session since0.5.6 and scene retention40seconds with hard60second limit since0.5.4. code_audit independently confirmed current constants. The archival README must remain byte-identical in handoff, with these corrections in new handoff documentation.
