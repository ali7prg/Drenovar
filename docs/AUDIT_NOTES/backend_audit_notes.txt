RUNTIME STRUCTURE

1. gameplay37/server/core.mjs is the authoritative domain engine. It controls training, resource clearing, construction, starter rewards, trading, hospital healing, marches, city hunting, commands and idempotency.
2. gameplay37/server/world62.mjs provides shared world placement, relocation, world march routing, shared Velkor encounters and PvP.
3. gameplay37/server/hosted.mjs adapts the domain to Cloudflare D1 using one revision-checked JSON realm snapshot. It reads the production identity injected by Sites or the authenticated identity passed by native-session.mjs.
4. gameplay37/server/native-session.mjs implements native login confirmation, exchange, session validation/revocation and forwarding of native game actions to the same hosted adapter.
5. hosting37/app/api/[...path]/route.ts routes /api/native/ to handleNative; ordinary game API requests go to handleGame with worldEnabled=true.
6. hosting37/worker/index.ts is the Vinext Worker entrypoint. hosting37/vite.config.ts enables nodejs_compat and the declared DB binding.
7. gameplay37/server/engine.mjs uses Node's built-in node:sqlite as a local domain repository. gameplay37/server/http.mjs is an older isolated development service with cookie-based local sessions; it is not the hosted native-session service.
8. gameplay37/server/memory-sql.mjs is an in-request SQL-shaped adapter over maps used inside the hosted snapshot; its process-local maps are not production persistence.
9. Root dist contains authored browser and shared rules/assets, not exclusively disposable build output. Server modules import 21 source modules from dist. Deleting dist breaks the backend.
10. dist/server and hosting37/dist are generated deployment output and are absent in this checkout. A developer must rebuild them if needed; their absence is not loss of the authored backend.
11. Root .openai/hosting.json and hosting37/.openai/hosting.json declare DB and the same existing Site project. They are hosting metadata, not secret credentials.
12. README.md at root documents much older milestones. gameplay37/README.md also has obsolete statements such as no PvP, no world Velkor and no legacy migration. Current source and current tests supersede those historical passages.

NATIVE LOGIN AND API CONTRACT

1. main.gd generates a random 32-byte proof rendered as 64 lowercase hexadecimal characters.
2. The client derives challenge=SHA256(proof), opens /api/native/approve?challenge=<challenge> in the browser and displays the first eight challenge characters as a confirmation code.
3. GET approve requires the existing ChatGPT identity; otherwise it redirects to /signin-with-chatgpt. POST approve checks same-origin Origin and the eight-character code.
4. The server inserts a native:<challenge> record with approval lifetime five minutes. An already-used challenge is rejected.
5. POST /api/native/exchange with JSON {proof} yields 202 while approval is pending, 410 after approval expiry, or a session string on success.
6. Native sessions last 12 hours from their creation. There is no refresh-token implementation in the inspected file.
7. X-Drenovar-Session authenticates native requests. It is a 129-character challenge.token value. The server stores a token hash rather than the clear token.
8. Forwarded native requests discard supplied oai-authenticated-user-id/email and use the user identity bound by approval.
9. Allowed native actions: GET /api/native/game/state; POST /api/native/game/session/new; POST /api/native/game/command; POST /api/native/game/march-preview; GET /api/native/game/account; POST /api/native/game/profile/select. Native legacy import is not in this allowlist.
10. POST /api/native/logout marks the session revoked.
11. JSON mutations send Content-Type: application/json and Origin equal to endpoint. Commands require Idempotency-Key matching the domain's 8–100-character format. X-Drenovar-Player prevents accidental commands against a different selected profile.
12. A retried command with the same key and body is not applied twice. Reusing a key with a changed body is rejected. Hosted CAS conflict returns a retryable response after six attempts.
13. Standard request body limit is 16 KiB; browser profile import allows 512 KiB. Public game responses may be larger. The native HTTP client limits bodies to 8 MiB.

SAVE SYSTEM AND DATABASE SCHEMA

Production binding: Cloudflare D1 DB.
Migration: drizzle/0000_closed_nightmare.sql.
Table: game_realm37(id TEXT PRIMARY KEY NOT NULL, revision INTEGER NOT NULL, data TEXT NOT NULL).
Main realm key: development-37.

Main realm data includes repository and accounts, plus profiles40 and legacy import metadata when used. accounts maps authenticated user identity to selected player ID. profiles40 associates multiple owned profiles.
repository contains arrays representing maps named players, encounters, commands and sessions:
- players: key player ID, value containing a JSON state string;
- encounters: key encounter ID, value containing owner and JSON state string;
- commands: key encoded player/key pair, value containing command signature and response;
- sessions: key hashed local session token, value containing player and expiry.

Player JSON includes city, armies, wounded, healing, items, reports, lastAt and, when applicable, worldSlot62, worldOrders62, nickname, origin and migration/eligibility metadata. city includes its economic, construction, military, resource-clearing and tutorial state.

Hosted reads reconstruct a request-scoped repository, apply server-time advancement and commands, then update the complete realm JSON using WHERE revision=<old revision>. Accounts, troops, rewards, casualties and receipts are committed with that snapshot. The snapshot size check is 8*1024*1024 characters in JavaScript JSON string length, not a precise UTF-8 byte bound. It returns 503 when exceeded. This design is for a small development realm, with contention and growth limitations; no load-capacity claim is justified.

Native session approval records use separate native:<challenge> IDs in the same D1 table. Their data contains user, approvalUntil, sessionUntil, tokenHash and optionally revoked. These records are not a substitute for the gameplay save snapshot.

Native local files:
- user://drenovar-session.bin: encrypted session token, temporary sibling ending .tmp during atomic rename. Key derived from DRENOVAR-iOS-session-v1: plus OS.get_unique_id(). This is an encrypted local token file, not an iOS Keychain implementation and not a complete game save. Do not bundle a real user's copy.
- user://battle-results.cfg: last announced report ID per profile under journal; presentation state only, not rewards or economic state.
- project/assets/game.json: packaged data plus demo/starter state. It is not a downloaded production save or proof of live account progress.
- README mentions user://device-render.json for a rendering measurement; verify its writer separately before claiming it is always present.

The older standalone http.mjs adapter uses a real SQLite file at DRENOVAR37_DB, default /tmp/drenovar38-development.sqlite, and a local cookie session. Its tables are players, encounters, commands and sessions. It is not interchangeable with a copied production D1 row or the in-memory native test realm.

No actual production D1 export, live player data, native token file, signing certificate or provisioning profile was obtained in this audit. Source handoff does not imply transfer of server access or live progress.

CURRENT GAME RULES FOUND IN SERVER SOURCE

No final campaign win, seasonal victory or terminal account defeat is implemented in the inspected domain files. Concrete outcomes are encounter/PvP victories and defeats, troop casualties and continuing settlement progression.

City hunting:
- New ordinary sessions spawn three city Tenerys encounters at levels 1, 2 and 3.
- Required hall levels are 1, 3 and 5 respectively.
- A party may contain at most 200 soldiers; the server's active roster is the ten English units from dist/army/roster.js.
- At most three active armies across city and world orders.
- Simulate() runs server-side in 200 ms steps up to 180 seconds. Creature HP reaching zero is victory; surviving creature at termination is defeat.
- A living soldier survives. An incapacitated soldier is classified wounded with 60% seeded probability; otherwise dead.
- After a city victory, food, items and XP are added once and a report is stored. Surviving troops return after their travel time; wounded enter the hospital pool, dead troops are lost.
- Tenerys food rewards for L1/L2/L3: 1500/4000/10000. Base respawn four hours multiplied by level. The first Tenerys victory sets the tutorial firstHuntWon flag.
- Defeat restores the city creature to alive/full HP at battle end; the player's casualty result remains.

Shared world hunting:
- Current actual spawns are three shared Velkor targets. Kamneklyk and Dragor have catalog definitions/assets but are not spawned by world62.mjs.
- Velkor food rewards before capacity adjustment: 1000/3000/8000. Antlers: 5/15/30. XP: 15/40/100. Base respawn six hours multiplied by level.
- A reserved or still-defeated target cannot be attacked simultaneously.
- World reward award() caps resource additions to available storage capacity. Therefore food can legitimately become 0 in the report when current food is at or above cap. This differs from city hunting, which adds food directly and can exceed production/storage limits. This is verified source behavior, not proof that it caused a particular iPhone complaint; it should be explicitly reviewed with the owner.
- World victory awards antlers/XP and food; it does not follow the city branch's additional hides/rare-drop handling.

PvP:
- Both settlements need hall level at least II and competitive eligibility. Imported noncompetitive/legacy settlements are excluded.
- Defender's healthy garrison is reserved on arrival, at most 200 units, iterated by sorted unit ID.
- duel62 compares summed unit power. Attacker wins only when attacker power > defender power. A tie favors the defender.
- PvP battle duration is 6000 ms. Casualty ratios are deterministic from power and seed: loser casualty ratio .85; winner ratio min(.65, opponentPower/ownPower*.55). Wounded share of casualties is .55 through .75 according to seed and side offset, with integer rounding.
- Victorious attacker receives up to 30 coins only if defenders existed; victorious defender receives up to 30 coins. award() applies capacity limits. No resource plunder or city destruction is shown by this code.
- Both players receive reports; surviving defenders return to garrison, wounded join their hospital pool, attacker survivors travel home.

Training v92 compatibility:
- Backend always passes chargeResources:true to recruit(). Public state advertises trainingUsesResources:true.
- Unlimited legacy saves require paidTraining:true from the client to prevent a silent charge behind an older free-training UI.
- Native 0.5.9 main.gd reads trainingUsesResources and sends paidTraining:true. This contract is compatible by source inspection.
- Cancellation refunds stored charged cost and repeat requests do not duplicate refund. An old free order does not produce a paid refund.

REPRODUCIBILITY RISKS / REQUIRED QUALIFICATIONS

1. Native .github/workflows/drenovar-ios.yml expects branch native-ios-godot and a native-ios directory, but the supplied backend checkout exposes only main and no native sources. The workflow must be placed in the intended real repository layout; do not assume it is installed remotely.
2. tools/fetch-web84-assets.mjs downloads mutable live-site URLs and verifies pinned SHA-256 hashes. The native manifest has 248 entries. Comparing them to this exact v92 checkout gave 247 matches and one mismatch: city/military.js. No pinned source file was absent after mapping creature-assets37 to gameplay37/assets. A clean CI fetch against v92's changed military.js can fail the pinned hash check. Do not silently update the hash without checking intended native data generation.
3. Native source already contains project/assets. Preserve those packaged assets to avoid making this handoff depend solely on mutable website downloads. Regenerating game.json from v92 rules is a source change and requires a reviewed update/verification.
4. Native pipeline downloads Godot 4.6.3/template and runs macOS/Xcode for a fresh IPA. Those external dependencies are not included just because source is archived.
5. tools/repack-tested-engine.py needs a previous matching unsigned IPA plus newly exported PCK. It reuses the binary byte-for-byte; it is not an Xcode rebuild and deliberately removes prior signing/provisioning. Version is set to 0.5.9, build 19.
6. Native README contains stale wording that session exists only in RAM; session_store.gd now persists it. The authoritative description should follow current code.
7. Local loopback test uses an ephemeral realm and fake identity, not native browser authentication, real production D1 or physical iPhone networking.
8. Native session TTL is 12 hours. Expiration requires reauthentication; distinguish that intended behavior from a spontaneous crash/reload. No diagnosis of the user's reload issue was made here.
9. Whole-realm CAS, 8 MiB-character guard and growing reports/command receipts impose capacity risks. A full public multiplayer load benchmark was not performed.
10. Source tests cannot certify Metal rendering, sustained iPhone 12 FPS, temperatures, input latency, App Store eligibility or code-signing success.
