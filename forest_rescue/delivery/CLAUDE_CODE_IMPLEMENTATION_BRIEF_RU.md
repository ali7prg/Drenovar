# DRENOVAR — «Лес потерянных»: инженерное распоряжение

## Обязательный результат

Используй приложенные материалы и реализуй описанную систему в существующем DRENOVAR. Доведи работу до функционирующего игрового результата: окружение размещено, приключения доступны, взаимодействия и анимации работают, прогресс сохраняется, награды проверяются, существующие функции не сломаны. Не останавливайся на плане или отчёте о распаковке. Если отсутствует обязательный пакет или доступ, точно укажи, какой именно, и продолжай независимые задачи. Не заявляй об интеграции или тестировании без фактического выполнения.

Последнее распределение ролей пользователя: автор комплекта производит концепцию, изображения для моделирования, данные, звук, проверяемые модули и инструкции; Claude Code производит итоговые 3D-модели, риги, анимационные клипы и интеграцию. Поэтому PNG в art — визуальные ориентиры. Они не являются GLB, текстурным атласом, UV, скелетом или готовой анимацией. Передавать картинки в плоскости вместо обещанных персонажей/деревьев нельзя. Изготовь реальные ресурсы по производственному плану; если качество рига/движений недостижимо доступными инструментами, покажи конкретный незавершённый ресурс и продолжи независимые задачи. Не подменяй его примитивом с заявлением «готово».

## Игровой опыт и точный объём

Гнедая кобыла Искра без всадника выходит из леса и ведёт выбранный игровой отряд к пленникам. По мере авторитетного перемещения лесной туман плавно открывает карту. На 12 полянах находятся по три человека; каждая имеет пять заданий: обнаружить место → решить локальную задачу и получить артефакт → победить стража → потратить артефакт на открытие клетки → проводить троих домой. Первым стражем обязательно является Тенерис первого уровня. Четыре акта позволяют выбирать порядок трёх полян внутри акта. После спасения всех36 людей открывается отдельная арена огромного двуногого динозавра Пращура (`ancient_maw`); в финале пленников нет.

Это система исследования окружения поселения с привычной стратегической камерой. Отряд перемещается по выбранным путям, лошадь ждёт/оглядывается и ведёт его. Третье лицо, управление джойстиком или отдельная новая игра не подразумеваются. Представители отряда не должны изменять настоящую численность армии или заменять серверный расчёт боя.

Уникальные сцены/тексты/задания: `docs/CONCEPT_RU.md`, `docs/CAMPAIGN_BIBLE_RU.md`, `docs/NARRATIVE_RU.md`, `data/campaign.json`, `data/dialogue.ru.json`, `data/ui.ru.json`. Таблица экономики: `data/economy.json` и `docs/ECONOMY_RU.md`. Все ID стабильны; не создавать отдельный расходящийся набор в UI.

```sh
python3 tools/verify_delivery.py /absolute/path/to/packages --extract /absolute/path/to/empty_output
```

ZIP независимы, все имеют общий корень `DRENOVAR_Forest_Rescue/`, пути не конфликтуют. Скрипт проверяет размер≤30_000_000, SHA-256, CRC, зависимости, пути, распаковку и обратные хеши. Лошадь подстраивается под отряд и ждёт, не убегает за границу кадра.

## Квесты, бой, артефакты и награды

Reference API и точные поля — `docs/CODE_AND_PERSISTENCE_RU.md`, `data/persistence-contract.json`. Новый namespace `p.adventures.forest_rescue_v1`; механизм отдельно `p.adventureMechanisms.forest_rescue_v1`; autoRefill preference отдельно. Только отсутствие нового namespace можно лениво мигрировать в initialState; неизвестную/повреждённую версию нельзя молча сбрасывать.

`code/forest-rescue.mjs` задаёт фазы, 60задач, artifact invariant, виды/уровни стражей и escrow. `code/mechanisms.mjs` — четыре варианта: поиск следов, порядок рун, лебёдка, парные упоры. Предложенные boolean proofs из примера не считаются настоящей защитой: адаптер должен получить действительные данные сервера о прибытии, механизме, результате боя и сопровождении ровно трёх правильных NPC. Клиент НЕ передаёт успех, награду, ownerId, время, capacity или состояние.

Интеграция в существующий command/tx/commands receipt; `reference-transaction.mjs` — исполнимый пример транзакции, не альтернативная production-база. Артефакт, completed-step, уникальный reportId, escrow/кошелёк и квитанция пишутся одной транзакцией; hosted CAS перечитывает новый snapshot при конфликте. Повтор исходного request key возвращает текущее состояние без повторных effects; другой ключ не позволяет повторить award. Новые поля явно включить в безопасный publicState. Legacy import не может создать подтверждённый новый прогресс и ресурсные выплаты.

Бонусы кампании: food2_325_000, wood2_385_000, stone1_590_000, iron1_025_000, coins190_000, всего7_515_000. Обычную настоящую первую боевую добычу сохранить отдельной строкой, она не входит в эту сумму. Campaign guardians одноразовые без respawn farming; обычную охоту не ломать. XP/уровень ратуши не подменяют друг друга. Уровни существ2/3 требуют ратушу3/5 по текущим правилам; покажи причину ограничения, не молча запирай пользователя.

Склад базового города ограничен2000/ресурс. Весь бонус сначала попадает в серверный reserve escrow: earned=claimed+pending. «Заполнить склады» переводит доступную вместимость, остаток сохраняется без срока. По добровольной настройке auto-refill (`code/reserve-refill.mjs`) пополнять склады из reserve в той же транзакции после настоящего подтверждённого расхода. Без фонового polling, без пересмотра цен/capacity, без начисления на возврате/дубликате. Это обеспечивает реальные большие награды без тысячи ручных запросов. Указанные суммы — авторская щедрая экономика, не прошедший production-баланс.

Финальный `ancient_maw` новый, не добавляй его в каталог под вымышленным старым ID. Три фазы и атаки заданы campaign.json и согласованы animation_manifest. Численные параметры — кандидаты для симуляций/плейтеста. Босс должен читаться по предупреждениям/отходу/восстановлению, а не мгновенно убивать без обратной связи. Выплату запускает подтверждённый финальный battle report, не конец death clip. Новая pause-функция не останавливает старые серверные бои, очереди и общий мир — объяснить это в UI.
