# Художественное производство и границы изображений

В art переданы18 настоящих сгенерированных PNG. Все сохранены в исходном разрешении, без уменьшения, перерисовки кодом или выдачи upscale за дополнительную детализацию. Они служат визуальными ориентирами: это не готовые3D, не UV-развёртки, не бесшовные PBR-карты и не motion capture. Точные размеры/хеши — qa/ART_INVENTORY.json. Исходные запросы — sources/art. Финальный пользователь явно поручил моделирование и анимацию Claude Code.

## Приоритет источников и обнаруженные ограничения

1. Состояния, цены, награды, названия, путь и размеры игровых пятен определяются JSON/инженерными документами. Иллюстрация не меняет navmesh или экономику.
2. Для внешности новых персонажей приоритет у turnaround-листов. В постановочных картинках встречаются другие плащи/седло лошади: не копировать эти отступления. В финальной модели Искра без седла; зелёная лента на недоуздке. Для уже существующих видов сначала восстановить оригиналы, сравнить их с новым направлением, сохранить species ID/правила/уровни. Новый Пращур имеет отдельный ID.
3. Лист клеток содержит несовпадения стороны петли в отдельных видах. При моделировании выбрать единую сторону каждой двери, положение оси, запор и безопасный сектор движения. Картинка не является механически доказанным чертежом.
4. Мост на изображении показывает конструкцию; инженерная длина27м из атласа имеет приоритет над художественной перспективой и упомянутыми в исходном промпте26м. Стойки не должны перекрывать поток/путь. Скалы и waterfall в общей картине — композиционные идеи, не разрешение произвольно сдвигать реку.
5. Иллюстративные надписи могут быть на английском. В игре использовать только локализованные строки из data/ui.ru.json и data/dialogue.ru.json, не вырезать текст изPNG. Изображённый прогресс1/3 — эскиз UI, настоящие значения из состояния.
6. Keypose-листы не гарантируют одинаковую длину конечностей и идеальные контакты во всех кадрах. Аниматор строит движение на одном принятом риге, проверяет foot sliding/пересечения, временную кривую и темп. Нельзя просто склеить панели в видео и назвать скелетной анимацией.

Эти ограничения явно переданы, а не скрыты за статусом «готов к импорту». Изображения достаточны для постановки задачи моделирования; финальная геометрия и материалы требуют отдельной художественной приёмки.

## Полный список для моделирования

`data/asset-production-plan.json` содержит требуемые группы, соответствующие картинки и ожидаемый результат. Для каждого пункта сохранять source (Blender/другой редактор), рабочие текстуры, export GLB, описание rig/clips, LOD и контрольные данные. Статус будущих моделей `requires_further_development`. Созданные в этом комплекте PNG остаются `visual_reference`.

Целевые соглашения: метры,+Yверх,+Zвперёд; feet/root на поверхности; одинаковые skeleton naming и retargeting у взрослых NPC; младшие персонажи не обязательны. Мелкие предметы имеют единый масштаб и pivots у реальных осей. Сглаживание normals/касательные, ориентирование roughness linear/baseColor sRGB, умеренные металлические отражения. Основные материалы леса: дубовая кора, хвоя/листва, земля, мох, известняк, дерево клеток, железо/бронза, ткань. Сохранить качественные исходники; мобильные2048/1024/512 выбирать по texel density и экранному размеру, не по лимиту передачи. Карточки листьев alpha-test, минимум прозрачного overdraw.

Треугольники/кости и анимационные LOD заданы animation_manifest; итоговый активный бюджет окружения≤110k, дополнение с актёрами≤180k является стартовым ориентиром, а не измеренным пределом устройства. Не превращать каждый лист дерева в отдельный прозрачный объект. Для каждого вида дерева минимум три силуэтных варианта из общего материала, затем instancing с детерминированными transforms. Камень/стволы/кусты/grass — отдельные группы culling. Нельзя загрузить все исходники полного качества в runtime.

## Проверка произведённых Claude Code ресурсов

GLB Validator без ошибок; импорт целевым Three GLTFLoader; все клипы с конечными матрицами; проверка root bound/feet contact/плавных переходов; collision и navigation без застреваний; уникальная часть NPC-снаряжения не ломает shared-material кеш. Для босса показать видео walk/turn/attack/recovery/death в игровой камере. Показать сравнение с этими референсами и отклонения. После этого измерить реальные renderer.info, CPU/GPU и долгий прогон iPhone12. Готовность PNG не заменяет эти проверки.

Новая панель18 показывает туман, уведомление и появление Искры. Золотое свечение/силуэт ратуши и перспектива — художественный ориентир, не разрешение менять реальную базу. В третьей панели камера ниже стратегической; в игре сохранить обычную камеру с мягким ограниченным приближением. Надписи брать из JSON, не вырезать из изображения. Лошадь производить по каноническому turnaround, включая белую звезду на лбу. На иллюстрации отсутствует кнопка «Позже» и вариант reduced motion: их всё равно реализовать по контракту.
