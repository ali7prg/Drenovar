# Замер «Леса потерянных» на физическом iPhone 12

В облачной среде этой работы нет ни iPhone, ни Mac с Xcode, поэтому замеры на устройстве
**не выполнены**. Ниже приведена процедура, которой их можно провести. Цифры, снятые
на настольном программном рендере (llvmpipe), к iPhone не относятся и подписаны отдельно.

## 1. Сборка

На Mac с Xcode и шаблонами Godot 4.6.3:

```sh
python3 godot/tools/ios-template.py "$HOME/Library/Application Support/Godot/export_templates/4.6.3.stable/ios.zip"
bash godot/tools/package-ios.sh build/ios
```

Получится `build/ios/DRENOVAR-unsigned.ipa`. Подпишите его тем же способом, что и прежние
тестовые сборки, и установите на iPhone 12. В настройках игры слой леса включён флагом
`forest_rescue_v1`. Для сравнения «до/после» снимите одни и те же сценарии с флагом
и без него.

## 2. Сервер

Сервер v92 без модуля приключения отдаёт состояние без `state.adventure`. Тогда клиент
показывает закрытый туман с надписью «Приключение недоступно на этом сервере». Для полного
сценария нужен сервер с подключённым модулем (`forest_rescue/server/INTEGRATION_V92.md`)
или локальный realm:

```sh
node forest_rescue/server/local-realm/server.mjs
```

Realm слушает порт 8418 и доступен телефону через Mac в той же сети.

## 3. Сценарии (каждый — после 30 с прогрева)

| № | Сценарий | Что делать |
|---|---|---|
| S1 | Город до ратуши III | Открыть город, 60 с медленно водить камеру над туманом вокруг базы |
| S2 | Открытие на ратуше III | Довести ратушу до III и записать вступление (12 с) целиком |
| S3 | Долгий пролёт над лесом | 3 мин непрерывно водить камеру по всем 16 чанкам; затем зум 32→140 |
| S4 | Поход отряда | Отряд с лошадью идёт от входа к месту 1, туман рассеивается (запись видео) |
| S5 | Бой со стражем | Тенерис I: весь бой с презентацией ударов |
| S6 | Освобождение и эскорт | Открытие клетки ключом, выход троих, путь домой |
| S7 | Пращур | Первый вход на арену, все три фазы, телеграфы атак |
| S8 | Нагрев | 15–20 мин без перерыва: S3 и S4 по кругу; каждые 5 мин снимать замер |
| S9 | Жизненный цикл | Уход в фон на 1 мин и возврат; блокировка экрана; слабая сеть (Network Link Conditioner, 3G) |
| S10 | Ориентации и звук | Portrait/landscape, safe-area; переключатель «без звука» |

## 4. Что фиксировать

* Окно «Меню → Плавность на этом устройстве» → «Скопировать замер»: медиана и 95-й
  перцентиль кадра, кадры при движении камеры, вызовы отрисовки, примитивы, экземпляры,
  размер буфера, GPU. Снимать в конце каждого сценария.
* Xcode Instruments: шаблон **Game Performance** (FPS, CPU/GPU time, thermal state) и
  **Allocations / VM Tracker** (пик памяти); для S8 — график thermal state.
* Видео экрана (встроенная запись iOS) для S2, S4, S5, S6, S7 — проверка плавности
  анимаций и тумана глазами.

## 5. Ориентиры (это цели, а не измерения)

Ориентиры взяты из `delivery/docs/PERFORMANCE_AUDIT_RU.md` и `world-atlas.json → streaming`:
* стабильные 30 fps: кадр p95 ≤ 33,3 мс, p99 ≤ 40 мс;
* видимая геометрия нового окружения ≤ 110 тыс. треугольников, вместе с актёрами ≤ 180 тыс.;
* ≤ 4 полных и ≤ 8 облегчённых чанков, прокси ≤ 1800 треугольников на чанк;
* наложение прозрачности в среднем ≤ 3 слоёв;
* масштаб буфера (DPR) ≤ 1,5;
* без роста памяти за 15 мин.

Не отключайте туман или персонажей ради цифр. Таймеры сервера и исход боя не зависят от FPS.

## 6. Что прислать

Скопированные замеры S1–S10, скриншоты Instruments, видео и модель телефона с версией iOS.
По этим данным оптимизации делаются точечно.
