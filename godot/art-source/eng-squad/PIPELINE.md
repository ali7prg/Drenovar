# DRENOVAR · ENG squad (ENG-01, ENG-02, ENG-03, ENG-04, ENG-06 + horse)

Рабочий документ производства пяти бойцов английского отряда по комплекту референсов
`references/` (архив `Drenovar-5-Units.zip`, SHA-256
`be685dd4d1a69d48db68a28b14bd103afbf3360d605ce95a096508f8e4158b2b`).
Задание целиком: `references/Drenovar-Claude-Code.txt` (12 этапов).

## Порядок работы

* Этапы 01–12 выполняются строго по порядку, на каждом этапе работает один профильный агент.
* После каждого этапа ведущий (основная сессия) сам открывает результат, сравнивает с
  референсами и либо принимает этап, либо возвращает конкретные замечания тому же агенту.
* Следующий агент получает только принятые ресурсы, исходные референсы и замечания.
* Агенты НЕ делают git commit/push — коммит делает ведущий после приёмки этапа.
* Агент не меняет файлы вне своей зоны без явной причины; любое изменение чужого
  результата фиксируется в отчёте этапа.
* Каждое решение при расхождении рисунков и каждая реконструированная (невидимая на
  всех картинках) деталь записывается в `DECISIONS.md` (раздел своего этапа).

## Инструменты

```bash
. godot/art-source/eng-squad/pipeline/env.sh   # GODOT, BPY, PROJECT, SQUAD, REFS, WORK
"$BPY" -I script.py -- args                   # Blender 5.3 (bpy) — моделирование, риг, анимация, экспорт glTF, Cycles
godot_headless -s qa_script.gd                # Godot 4.6.3 без окна (импорт, проверки)
godot_render 1366x630 -s capture.gd           # Godot 4.6.3, Mobile renderer, Vulkan lavapipe + Xvfb (кадры/видео)
"$GODOT" --headless --path "$PROJECT" --import  # переимпорт ресурсов после изменения GLB/PNG
ffmpeg, ImageMagick (convert/identify), numpy, Pillow — в $BPY venv и в системе
```

* Временные файлы и черновые рендеры — в `$WORK/stageNN/` (scratchpad, не в git).
* В git попадает только принятое: исходники `.blend`, скрипты `pipeline/`, текстуры
  `textures/`, откалиброванные референсы `refs-calibrated/`, отчёты `reports/stageNN-*/`,
  игровые ресурсы в `godot/project/assets/army/eng-squad60/`, QA-скрипты в `godot/project/`.
* Изображения отчётов — PNG/JPEG разумного размера (до ~1 МБ каждое), видео — MP4 H.264
  короткие (до ~10 с, до ~3 МБ).
* Внутри `godot/project` не класть `.blend` (Godot попытается их импортировать).

## Соглашения

* Единицы — метры. Godot/GLB: +Y вверх, +Z вперёд (лицо бойца смотрит в +Z), правая рука
  бойца на −X (как у существующих ENG-моделей). В Blender боец смотрит в −Y, правая рука на −X
  (экспорт glTF с +Y up даёт +Z вперёд).
* Право/лево — со стороны самого бойца. `profile_facing_left/right` — направление взгляда в кадре.
* Скелет пехоты совместим с проектом: 19 костей `Hips, Spine, Chest, Neck, Head,
  RightUpperArm, RightForearm, RightHand, LeftUpperArm, LeftForearm, LeftHand,
  RightThigh, RightShin, RightFoot, RightToe, LeftThigh, LeftShin, LeftFoot, LeftToe`
  (+ дополнительные кости предметов, если их вводит этап 04/07 — фиксируются в отчёте).
* Конная единица: один GLB, один скелет «лошадь + всадник» по образцу существующего ENG-06
  (`HorseRoot`, `HorseBack`, …, всадник `Hips…` дочерний к `HorseBack`), отдельные
  редактируемые `.blend` для лошади и всадника.
* Имена клипов: контроллер ищет клип по подстроке без учёта регистра в
  алфавитном списке анимаций (`landscape.gd: play_animation`). Нельзя давать клипам имена,
  которые содержат `walk`, `idle`, `run`, `hit`, `death`, `attack` и стоят по алфавиту раньше
  основного клипа (например, `Attack_Windup` перед `Attack` допустим только если основной клип
  — `Attack`, так как `Attack` < `Attack_Windup`). Обязательные имена задаёт этап 01.
* Имена материалов несут ключевые слова для `src/warrior_visual.gd`
  (`skin`, `cloth`, `wool`, `linen`, `leather`, `wood`, `steel`, `iron`, `mail`, `brass`, `eye`, `horsecoat`, `horsehair` …).
* Выходные игровые файлы: `godot/project/assets/army/eng-squad60/ENG-0N-<name>60-lod1.glb`
  (оружейная/обучение) и `…-lod2.glb` (поле, марш, парад, бой) + внешние текстуры рядом.
