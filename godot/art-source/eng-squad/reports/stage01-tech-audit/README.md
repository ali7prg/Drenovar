## Коротко

* Пять ID актуальны: ENG-01 копейщик и ENG-02 мечник со щитом (группа INF-01), ENG-03 длиннолучник и
  ENG-04 арбалетчик (RNG-01), ENG-06 конный рыцарь (CAV-01). Каталог — `assets/game.json → unitModels`,
  `preview` = lod1 (оружейная, тренировка), `field` = lod2 (марш, бой, парад).
* Перемещением владеет контроллер `landscape.gd::present_armies`: позиция армии интерполируется по серверному
  `path` между `startsAt` и `arrivesAt`, бойцы стоят в слотах `formations.gd`, масштаб 1.15. Клипы — на месте
  (Hips/HorseRoot двигаются только по Y), корневого движения нет, `speed_scale` никогда не меняется.
* Клип выбирается по подстроке без учёта регистра в алфавитном (регистрозависимом) списке; бой — «скраб»
  (пауза + `seek(фаза·длина)`) без кроссфейда; переход в Idle/Walk — кроссфейд 0.16 с.
* **У ENG-02, ENG-03, ENG-04 нет клипа `Attack`** — в бою вместо него проигрываются `Sword_Drill` (3.8 с),
  `Bow_Draw` (4.0 с), `Crossbow_Reload` (5.0 с), сжатые в окно 1.0 с. `Run` и `Shield_Block` есть в файлах,
  но код их никогда не вызывает. Отдельной стойки блока или извлечения меча у ENG-02 в коде нет.
* Окно атаки `[at−490, at+510]` мс, фаза удара/прилёта = **0.49**, выпуск снаряда = **0.23**; `Hit` 400 мс,
  `Death` 700 мс и затем удержание последней позы. Стрела — жёлтый цилиндр `Arrow`, летит 260 мс от оси
  бойца (1.35 м над его точкой) к центру армии (+1.45 м), одна на событие, к руке/сокету не привязана.
* Клиент опрашивает `/state` раз в 0.8 с; окно атаки и полёт стрелы начинаются **до** времени события, значит
  визуал работает только если сервер присылает таймлайн боя заранее. Серверный код недоступен — проверено
  синтетически: при раскрытии событий «по факту» не видно ни одной стрелы и все замахи (раздел 8).
* Предметы (копьё, меч, щит, лук, арбалет, пика) — части skinned-мешей с весом 1.0 на `RightHand`/`LeftHand`;
  BoneAttachment, сокетов и отдельных костей предметов нет.
* Существующий Walk пехоты «шагает» со скоростью 0.46 м/с (×1.15), лошадь — 0.54 м/с; при марше 1.2 м/с опорная
  стопа скользит 0.23–0.37 м за контакт, в повороте 60° задние ряды — до 2.7 м (жёсткий поворот строя).
* На боевой камере мира (zoom 68) пехотинец ≈ 17 px в высоту (голова ≈ 3 px), рыцарь ≈ 29 px; на ближнем
  зуме (15) — 84 и 154 px; в городе (70/24) — 15/44 и 25/72 px.
* Godot генерирует 4–8 уровней mesh LOD; при zoom 68 рисуется ~3.3–3.8 тыс. треугольников пехотинца из
  ~21–22 тыс.; у рыцаря авто-LOD почти не работает (14.5 тыс. из 34.8 тыс.).
* Построен инструмент съёмки настоящей игровой сцены `godot/project/qa_eng_squad_capture.gd` + `pipeline/frames_to_mp4.sh`
  + `pipeline/foot_slide_report.py`; инструмент проверен, исключён из экспорта (проверено реальным `--export-pack`).
* Отдельного экспорта ресурсов для веб-клиента в этом репозитории нет (только iOS-пресет; `tools/*.mjs`
  импортируют ресурсы ИЗ веб-сборки).

## 4. Контроллер и владелец перемещения

```
сервер: path[], startsAt, arrivesAt, status, battleAt, battleEndsAt, events[], fallen[]
  → клиент: опрос /state каждые 0.8 с (5 с без похода), время = unix ms + смещение от последнего ответа
  → landscape.gd::present_armies (каждый кадр):
       доля = (now − startsAt)/(arrivesAt − startsAt) → точка армии p на ломаной path (по XZ, высота с рельефа)
       курс = направление между точками ±250 мс; армия рисуется, только если p+1 м в усечённой пирамиде камеры
       слот бойца = formations.field_slots (до 24 представителей) → смещение, повёрнутое по курсу
       в бою: разлёт (×1.22 вбок, +2.5/+4.0 м назад за 700 мс), каждый смотрит на p; в городе — круг 4.8/7.5 м
  → модель: клипы на месте, AnimationPlayer
```

* Корневого движения нет (проверено по каналам glTF): в `Walk`/`Run`/`Idle` у пехоты `Hips.translation` меняется
  только по Y (покачивание), у конницы так же `HorseRoot`; в `Attack`/`Spear_Drill` ENG-01 — выпад таза вперёд
  до 0.085 м с возвратом; в `Death` таз опускается (у ENG-06 `HorseRoot` смещается на 0.46 м вбок — падение).
  Двойного движения нет, но и связи шага со скоростью нет: `speed_scale` всегда 1.0.
* Поворот строя жёсткий: при смене курса весь строй вращается вокруг p за ~0.5 с, крайние бойцы скользят вбок.

## 5. Импортёр

`.import` всех 20 армейских GLB одинаковы (сверено по хэшу секции `[params]`): `meshes/generate_lods=true`, `create_shadow_meshes=true`,
`ensure_tangents=true`, `animation/fps=30`, `remove_immutable_tracks=true`, `import_rest_as_RESET=false`,
`gltf/embedded_image_handling=1` (извлечение), `apply_root_scale=true`, `root_scale=1.0`.

Импортированная сцена: `Node3D (имя файла) → Node3D (корень glTF) → Skeleton3D → MeshInstance3D (все skinned)`,
`AnimationPlayer` в корне (`root_node = ".."`, одна библиотека `""`). Тип цикла клипов после импорта —
`LOOP_NONE`; цикл включает контроллер. BoneAttachment3D нет.

Текстуры:
* пехота ENG-01..04 (и 08–10) использует ОДИН общий набор из 36 внешних PNG рядом с GLB (`cloth20-*`, `mail20-*`,
  `steel20-*`, … 512², `headSkin/eyeReal-albedo` 1024²). Импорт: `compress/mode=0` (без потерь), **без мипмапов**,
  RGBA8 → 1 МиБ на текстуру 512² в памяти, весь набор ≈ 42 МиБ;
* ENG-06: 26 изображений **встроены в GLB и одновременно извлечены** рядом (`ENG-06-knight-lod2_forgeWood-albedo.jpg`…),
  256–768², без потерь, с мипмапами, ≈ 47 МиБ; отсюда размер файлов 6.8/11.0 МБ.
* `warrior_visual.gd` ставит всем материалам `LINEAR_WITH_MIPMAPS_ANISOTROPIC`, что без мипмапов ничего не даёт.

Авто-LOD Godot: 4–8 уровней на поверхность (meshoptimizer, каждый ≈ вдвое меньше по треугольникам; уровни — только
новые индексные буферы, вершинный буфер общий, поэтому число вершин по LOD не меняется; треугольники по уровням —
`budgets.json → godot_lod_triangle_totals`). Правило выбора
(проверено рендером, `data/godot_lod_measured_ENG-01_field.json`): на каждой поверхности берётся самый грубый
уровень, у которого `edge_length × масштаб`, спроецированная на экран, ≤ 1 px
(`mesh_lod_threshold = 1`, `lod_bias = 1`):
перспектива — `edge·s·1366 / (d·2·tan(fovx/2)) ≤ 1` (d — расстояние камеры до бойца),
орто (город) — `edge·s·630 / size ≤ 1`.

На каких расстояниях включаются уровни (поверхности с наибольшим числом треугольников, поле ×1.15;
полностью по каждой поверхности — `data/godot_lod_table.json → switch`):

| Модель, поверхность | LOD1 | LOD2 | LOD3 | LOD4 |
|---|---|---|---|---|
| пехота, голова `headSkin` (5.3 тыс.) | 3 м | 6 м | 13 м | 34 м |
| пехота, кольчуга `mail` (4.9 тыс.) | 7 м | 12 м | 27 м | 79 м |
| пехота, ткань `cloth` (3.9–8.4 тыс.) | 9 м | 15–16 м | 31–35 м | 131 м+ |
| ENG-06, кожа/сбруя (5.8 тыс.) | 26 м | 314 м | — | — |
| ENG-06, шкура лошади (2.9 тыс.) | 51 м | 119 м | — | — |

(в городе — размер орто-камеры примерно в 1.27 раза меньше этих чисел). Поэтому при zoom 68 пехотинец рисуется
на 3–4 уровне (≈ 3.5 тыс. тр.), а рыцарь почти целиком в полной детализации.

## 8. События боя: формат, тайминги, стрела

Формат: `army.events` (или `army.battle.events`) — `[at, kind, unitId, index, hp]`, `at` в мс от `battleAt`;
`soldier_attack` — удар бойца `unitId:index` по цели в момент `at`; любой другой `kind` — удар существа по бойцу
(`hp` после удара, 0 = смерть); `army.fallen` — лежащие с начала боя.

| Состояние бойца | Условие | Фаза клипа | Особенность |
|---|---|---|---|
| death | `hp == 0` уже наступил (или в `fallen`) | (elapsed − hit)/700, затем 0.999 | важнее всех |
| hit | < 400 мс после удара по бойцу | (elapsed − hit)/400 | |
| attack | elapsed ∈ [at−490, at+510] | (elapsed − at + 490)/1000 | без кроссфейда на входе |
| idle | иначе | цикл | кроссфейд 0.16 с |

Нормированные моменты окна атаки: 0.00 — начало (at−490), **0.23 — выпуск снаряда** (at−260),
**0.49 — удар/прилёт** (at), 1.00 — конец (at+510). Для клипа `Attack` длиной 1.0 с это 0.23 с и 0.49 с.
Фаза зажимается в 0.999. Цель (существо) играет `Hit` с момента `at` ещё 420 мс.

Стрела (`draw_arrow`, только группа RNG-01: ENG-03, ENG-04, ENG-10): один `MeshInstance3D "Arrow"` на бойца
(цилиндр r = 0.023 м, неосвещённый #ffd480), видим при клипе attack в интервале [at−260, at];
старт `a = позиция бойца + (0, 1.35, 0)` — ось тела, не рука (= 1.174 м в единицах модели);
финиш `b = точка армии p + (0, 1.45, 0)` (там стоит существо); дуга +0.6·sin(πp); длина древка растёт до 13 % пути.
Одна стрела на событие; прилёт ровно в `at`.

Пример из телеметрии (`data/battle_timeline_example.json`, мир, опрос 800 мс, задержка 120 мс): ENG-01_0 с событием
на 600 мс — клиент узнал о бое на ~333 мс и показал удар с фазы 0.22 (замах пропущен), далее фазы совпадают
с расчётными до 4-го знака; удар существа с hp = 0 на 1400 мс — `Death` за 700 мс и стоп-кадр; у ENG-03 стрела
видна на фазах 0.23…0.49.

**Знает ли клиент события заранее.** Клиент получает их только с опросом (0.8 с). Контроллер начинает замах за
490 мс и стрелу за 260 мс ДО `at`, т. е. рассчитан на то, что сервер присылает таймлайн заранее (сервер считает
бой целиком: шаг 200 мс, до 180 с — `docs/AUDIT_NOTES/backend_audit_notes.txt`). Код сервера недоступен,
поэтому проверено синтетически (`data/event_reveal_test.json`, 46 ударов, 20 выстрелов):

| Раскрытие событий сервером | Показано окон атаки | С какой фазы | Стрел |
|---|---|---|---|
| весь таймлайн с первого «fighting»-опроса | 40/46 | 0.02 (первое — 0.42) | 16/20 |
| только прошедшие события | 18/46 | 0.62–0.82 (после удара) | **0/20** |

Даже в лучшем случае статус «fighting» приходит на 0–0.9 с позже `arrivesAt`, и первые удары начинаются
с середины. Если окажется, что сервер раскрывает события по факту, это ограничение клиента: этапу 09 нужно
показывать клип отдельно в тестовой сцене (инструмент это умеет: `--reveal=all|progressive`, `--poll`).

## 13. Инструмент съёмки `godot/project/qa_eng_squad_capture.gd`

Поднимает настоящий `src/landscape.gd` (мир или город) с синтетическим состоянием сервера и каждый кадр вызывает те же
функции, что `main.gd::_process`: `update_camera`, `present_armies`, `present_creatures`, в городе
`present_parade`/`present_workers`/`present_training`; опрос `/state` эмулируется (`stage.present(state)` на каждом
«ответе»). Игровые скрипты не меняются. Время сервера идёт фиксированным шагом 1000/fps, аниматоры двигаются тем же
шагом (`--fixed-fps`; если шаг не совпал — переключение AnimationPlayer в ручной режим, отмечается в телеметрии).
Кадры, которые не сохраняются, не рисуются (lavapipe рисует кадр мира ≈ 3.5 с).

```bash
. godot/art-source/eng-squad/pipeline/env.sh
cd "$PROJECT"
godot_render 1366x630 --fixed-fps 30 -s qa_eng_squad_capture.gd -- \
  --map=world --units=ENG-01:3,ENG-02:3,ENG-03:3,ENG-04:3,ENG-06:2 \
  --scenario=battle --camera=battle --fps=30 --seconds=6 --speed=1.2 --out="$WORK/cap/mix_battle"
pipeline/frames_to_mp4.sh "$WORK/cap/mix_battle" "$WORK/cap/mix_battle.mp4"
python3 pipeline/foot_slide_report.py "$WORK/cap/mix_march" --clip=walk
# подмена моделей без правки каталога (GLB должен быть импортирован: "$GODOT" --headless --path "$PROJECT" --import)
... -- --models='{"ENG-02":{"field":"res://assets/army/eng-squad60/ENG-02-swordsman60-lod2.glb","preview":"res://assets/army/eng-squad60/ENG-02-swordsman60-lod1.glb"}}'
... -- --models="$SQUAD/pipeline/models_eng_squad60.example.json"   # все пять целевых путей из contract.json
```

Параметры (все после `--`): `--map=world|city`, `--units=ID:N,…`, `--scenario=march|battle|idle|parade|armory`,
`--camera=battle|close|orbit|<zoom>` (мир 68/15, город 70/24; `orbit` — свободная камера `--orbit=дист,курс,наклон`
вокруг `--focus=ENG-02_0`, не игровая), `--follow=center|game|none` (`center`: центр строя в кадре на заданном
расстоянии, компенсируя то, что камера смотрит на y = 1; `game`: точно как `main.gd`), `--fps`, `--seconds`,
`--speed` (м/с по маршруту), `--turn` (поворот в середине пути, °), `--slope=0|1` (ровный участок или склон, ищется по
настоящему рельефу без деревьев на пути), `--at=x,z --heading=°`, `--yaw`, `--out`, `--models=<json|файл>`,
`--every`, `--format=png|jpg`, `--frames=0` (только телеметрия, работает headless за секунды), `--poll`, `--latency`,
`--reveal=all|progressive`, `--interval` (мс между ударами бойца, можно по ID), `--grid` (шаг сервера 200 мс),
`--deaths`, `--approach`, `--level`, `--warmup`, `--phases` (оружейная). Сценарий `armory` открывает настоящую
оружейную `main.tscn` (`show_recruitment`) и снимает экран и сам SubViewport на заданных фазах клипа
(отказывается работать, если в `user://` есть сохранённая сессия, чтобы не трогать живой сервер).

Выход: `frames/f_NNNNN.png|jpg` и `telemetry.json`. Заголовок: параметры, маршрут (точки, длина, уклоны,
загромождённость), времена `startsAt/arrivesAt/battleAt`, все события, таблицы клипов и rest-позиции костей моделей.
Кадр: камера, статус армии у клиента и число известных событий, время последнего опроса, у каждого бойца — запрошенный
клип, реальный клип, позиция/длина/фаза, мировые позиции Hips/Head/Chest/рук/стоп/носков/копыт (для стоп — высота
рельефа под ними), кости предметов и BoneAttachment (позиция + кватернион), экранные точки головы и земли, стрела
(видимость, центр, направление, длина, наконечник, хвост); у существа — клип и фаза.

`pipeline/foot_slide_report.py` — смещение опорной стопы/копыта в мировых координатах на неподвижной части контакта
(без 15 % краёв), скорость цикла относительно корня против скорости пути, отдельно прямые участки и повороты,
доля длины ноги; предложенные пороги 2 % и 5 %. `pipeline/frames_to_mp4.sh` — H.264 yuv420p.

* Ряды конницы 3.7 м при длине лошади ×1.15 = 3.66 м; на параде ряды 3.08 м при длине лошади 3.18 м — лошади
  уже сейчас пересекаются.
* `warrior_visual.gd`: материалы без ключевого слова (`ENG01_red`, `ENG01_dark`, `ENG01_bowstring`, `forgeShield`,
  `forgeShaft`, `forgeHeraldry`, `horseHoof`) остаются как импортированы.

## 16. Веб-экспорт и исключение QA из экспорта

* В репозитории нет экспорта для веб-клиента: `export_presets.cfg` содержит только пресет iOS; `godot/tools/*.mjs` —
  загрузка закреплённых файлов веб-сборки (`fetch-web84-assets.mjs`), импорт веб → Godot с генерацией `game.json`
  (`import-web-assets.mjs`), пересборка манифеста (`capture-source-manifest.mjs`) и тестовые серверы
  (`test-realm.mjs`, `test-ios-session.mjs`). Web-пресета, шаблона и `.wasm` нет (это же в
  `docs/AUDIT_NOTES/assets_export_notes.txt`).
* Фильтр пресета iOS: `exclude_filter="benchmark*,qa_*,profile_*,tests/*,extension_api.json"`. Проверено
  экспортом `godot --headless --export-pack "iOS"`: в пакет записано 1496 файлов, ни одного `qa_*`/`benchmark*`/`tests/*`;
  новый `qa_eng_squad_capture.gd` и его `.uid` исключаются тем же правилом. Утилиты `pipeline/` лежат вне `godot/project`.

## 17. Риски интеграции (для этапа 11)

* `game.json` порождается `tools/import-web-assets.mjs` из веб-сборки — повторный запуск вернёт старые пути `*27`;
  workflow `godot/.github/workflows/drenovar-ios.yml` делает это перед сборкой IPA.
* `tools/verify_drenovar_asset_snapshot.py --require-complete` сверяет SHA-256 `game.json` среди 732 исходных
  файлов — правка каталога даст «mismatched».
* Старые GLB и общие PNG пехоты закреплены в `assets/original-assets.json` и `tools/web84-sources.json` —
  не перезаписывать, класть новое в `assets/army/eng-squad60/`.
* Общие текстуры пехоты используются ENG-08/09/10 — не менять их на месте.
* Связь шага со скоростью, плавный поворот строя, IK стоп на склоне и точка вылета стрелы из руки требуют правки
  `landscape.gd` (сейчас скорость клипов фиксирована, строй вращается жёстко, стрела стартует с оси тела).

## 18. Ограничения и что не проверено

* Серверный код (`ali7prg/drenovar-server`) недоступен: формула скорости марша, интервалы ударов, состав `kind`
  и то, присылает ли сервер таймлайн боя заранее, не проверены. Все бои и марши — синтетические, параметры
  записаны в телеметрии; скорость 1.2 м/с и интервал 2 с — допущения теста, не данные игры.
* Живой сервер не запрашивался (в том числе публичные файлы веб-сборки).
* Рендер — программный Vulkan (lavapipe), не Metal и не iPhone; производительность и сжатие текстур на устройстве
  не измерялись. Счётчик примитивов считался без теней.
* Высота «до верха головы» на экране — по кости Head + 0.226 м модели; оружие выше головы (копьё, пика) не учтено.
* Захват видео рисует только сохраняемые кадры; при `--every>1` промежуточные кадры моделируются, но не рисуются.
* Камера `center` в мире — поза, достижимая игроком панорамированием/зумом, но не идентичная `followed_army`
  (для точного поведения `--follow=game`).
