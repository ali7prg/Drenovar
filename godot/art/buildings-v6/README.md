# DRENOVAR V6: архитектура VI–XI

Версия ассетов: `DRENOVAR-V6-C1.0-ART1`. Источник визуальных требований — `13_BUILDING_PASSPORTS_RU.md` из C1.0. Здесь находятся рецепты всех 27 типов для VI–XI: 162 самостоятельных сцены, без масштабированных копий и без XII. Дополнительно создаются 27 исходящих сцен только для анимации перехода V→VI и отдельная модель тарана `SIEGE-RAM-01` для маршей и боя.

Капитальные корпуса и опоры на VI каменные; VII добавляет сланец и железные связи; VIII — аркады и специализированные пристройки; IX — усиленные опоры и организацию двора; X — тяжёлую кладку и рабочее оснащение; XI завершает силуэт. Поля, пшеница и сад остаются живыми. Дерево в воротах, снастях, телегах, настилах и инструментах служит их функции. Дворовые корпуса и показанный в мастерской таран не выдают дополнительных зданий или войск.

Используется существующий `project/tools/architecture/arch_kit.gd` и исходные PBR-материалы. Все 318 файлов `architecture-v2` из основы `4f7dcc228bc06d0ddc35e8292ca6e41cf8b4c95a` проверяются по SHA-256. Исходники Claude, сцены I–V, материалы, текстуры, свет и настройки рендера не переписываются. Оба варианта пищевого участка имеют модели; выбор 26 объектов поселения относится к серверу.

## Сборка в CI

Требуются Godot **4.6.3**, Node **24**, Python **3.12** с `venv`. Испытанная локальная среда: Linux x86_64, Godot 4.6.3, Node 24.22.1, Python 3.12.14. Python-инструмент фиксирует Pillow **13.0.0**, npm lock — meshoptimizer **1.3.0** и Khronos gltf-validator **2.0.0-dev.3.10**.

Из корня репозитория:

```sh
python3 godot/art/buildings-v6/build_all.py --bootstrap --package-dir /tmp/drenovar-v6-artifacts
```

`DRENOVAR_GODOT_BIN` может содержать путь к установленному Godot. `--bootstrap` создаёт игнорируемый `.venv`, устанавливает закреплённый Pillow и выполняет `npm ci --ignore-scripts`. После установки зависимостей этот флаг не нужен. Скрипт сначала выполняет `Godot --editor --import --quit`, поэтому существующий `.godot/imported` не требуется. Генерация моделей не требует Blender, исходного ZIP, сервера, сети, сохранений игроков или файлов из `/tmp`.

Для полной проверки повторяемости:

```sh
python3 godot/art/buildings-v6/build_all.py --bootstrap --check-reproducible --package-dir /tmp/drenovar-v6-artifacts
```

Команда выполняет две генерации и сравнивает SHA-256 всех выходных моделей, текстур и вспомогательных модулей. UID ресурсов задаются детерминированно; случайные редакторские `unique_id` удаляются из новых статических сцен. Результат и точная среда записываются в `reproducibility.json` и `toolchain.json`. Проверка в одной закреплённой среде не является заявлением о побайтном совпадении между Linux и macOS. Для одинаковых артефактов обоих клиентов рекомендуется один Linux job генерации с передачей native ZIP в существующий macOS job `package-ios`.

Если отдельному native job нужна самостоятельная генерация, достаточно Godot и Python:

```sh
python3 godot/art/buildings-v6/build_all.py --native-only --package-dir /tmp/drenovar-v6-native
```

Скрипт последовательно выполняет генерацию, переходы V→VI, фактическую загрузку сцен и физические проверки, сохранность старых файлов, упаковку web, независимое декодирование и Khronos-валидацию. Любая ошибка завершает job ненулевым кодом. Экспорт iOS/web должен выполняться после него.

## Выходы и подключение

Выходной корень: `godot/project/assets/city/architecture-v6/`.

| Выход | Назначение |
|---|---|
| `manifest.json` | `levels[type][level]` и `units[id]`: пути, масштаб 1, bounds, worker/site, стадия, материалы |
| `levels/<TYPE>-<6..11>.tscn` и `.res` | 162 новые native-сцены |
| `transitions/<TYPE>-5-to-6-from.tscn` и `.res` | 27 временных исходящих сцен V→VI |
| `units/SIEGE-RAM-01.tscn` и `.res` | Самостоятельная native-модель тарана |
| `web/<TYPE>-<6..11>.glb`, `web/SIEGE-RAM-01.glb` | 163 модели с lossless EXT_meshopt_compression |
| `materials/*.png` | Общие полноразмерные PBR-текстуры |
| `web/meshopt_decoder.mjs` | Закреплённый decoder с MIT license |
| `web/material_compat.mjs` | Восстановление исходных HDR-оттенков материалов |
| `native-assets.zip`, `web-assets.zip` | Раздельные тестовые артефакты, если задан `--package-dir` |

Бинарные выходы и staging игнорируются Git; рецепты, manifest, отчёты и контрольные суммы хранятся в ветке. `web/.gdignore` и `materials/.gdignore` исключают web-копии из native PCK. `web-staging` — промежуточные несжатые данные; их не нужно публиковать. Упаковщик ZIP их не включает.

Native-клиент объединяет `manifest.levels` с таблицей `levelModels`. Для VI–XI используется масштаб **1**, без старого увеличения модели на уровень. При переходе V→VI `upgrade_from_path` из строки VI заменяет только исходящую модель строительной анимации. Статическое V по-прежнему использует прежнюю сцену Claude. Переходные копии меняют только UV2.y, сохраняя исходные позиции, нормали и цвета побайтно.

`manifest.units["SIEGE-RAM-01"]` содержит native `path` и web `web` для одного тарана. Его геометрия и материалы создаются тем же `recipes.ram_display`, что и выставочный таран мастерской; это самостоятельная статическая модель из 1880 треугольников с масштабом 1 и направлением вперёд **+Z**. Перемещение, удар, повреждение и удаление уничтоженной машины выполняют клиенты по серверному состоянию. Ассет не задаёт боевых чисел и не создаёт юнитов.

Web-клиент загружает GLB по `row.web` и применяет оба совместимых модуля:

```js
import { MeshoptDecoder } from '/assets/city/architecture-v6/web/meshopt_decoder.mjs';
import { restoreNativeMaterialProperties } from '/assets/city/architecture-v6/web/material_compat.mjs';
loader.setMeshoptDecoder(MeshoptDecoder);
const gltf = await loader.loadAsync(row.web);
restoreNativeMaterialProperties(gltf.scene);
// Сохранить в кэш/клонировать после восстановления материалов. Масштаб = 1.
```

glTF ограничивает `baseColorFactor` диапазоном 0–1, тогда как оригинальные `oak_light`, `plank` и некоторые другие материалы Godot намеренно используют более яркий оттенок. Его точное линейное значение сохраняется в `extras.drenovarNativeBaseColor`; helper восстанавливает его в Three.js. Без helper такой оттенок был бы обрезан. Обычные материалы helper не меняет.

Геометрия, нормали, UV, касательные и цвета сохраняют float32. Сжатие не использует квантизацию, упрощение, уменьшение текстур или преобразование цветов в 8 бит. Каждый буфер сразу декодируется и сравнивается побайтно, затем проходит независимую проверку опубликованного GLB. Разрешение и декодированные пиксели каждой текстуры сравниваются с исходными PBR-файлами.

Native-материалы используют triplanar. Для стандартного glTF он преобразован в UV по доминирующей нормали грани при том же масштабе в метрах; на наклонных гранях расположение шва может отличаться. Геометрия и исходные текстуры сохраняются. Это ограничение формата следует учитывать при визуальной приёмке в браузере.

## Проверки и визуальная приёмка

| Отчёт | Что действительно проверяется |
|---|---|
| `validation.json` | 162 загруженные сцены, topology/materials, конечные координаты, границы участка, строительные каналы; 6 проходов ворот проверяются физическими объёмами; отдельно проверяются загрузка, материалы, bounds и направление тарана |
| `preservation-validation.json` | 318 прежних файлов неизменны; наличие 297 native-состояний, 270 визуальных переходов, 81 III→IV/V→VI/X→XI |
| `native-coverage-297.csv` | Построчная матрица native-моделей B01–B27/I–XI |
| `transition-validation.json` | 27 временных V→VI сцен, сохранность исходной геометрии |
| `web-validation.json` | Независимое побайтное декодирование каждого GLB, число треугольников, precision, внешние текстуры |
| `gltf-spec-validation.json` | Проверка glTF стандартным Khronos validator; оставленные UV2 могут отмечаться как неиспользуемые информационные поля |
| `texture-provenance.json` | Источник, SHA-256, разрешение и равенство пикселей текстур |
| `artifact-sha256.json` | Контрольные суммы всех распространяемых ассетов |
| `reproducibility.json` | Повторная генерация; появляется только при `--check-reproducible` |

Отчёты относятся к ассетам. Они не заменяют серверные проверки 270 оплачиваемых улучшений, миграций и межклиентского прогресса.

`review/VI-XI-01.png`…`03.png` показывают все 162 модели из настоящего Godot renderer при одинаковой камере и освещении. `review/SIEGE-RAM-01.png` показывает самостоятельный таран. Это изображения для художественной приёмки, не измерения скорости iPhone. Для повторного захвата при доступном X11/рендерере:

```sh
godot --audio-driver Dummy --rendering-method gl_compatibility --path godot/project -s ../art/buildings-v6/capture.gd
python3 godot/art/buildings-v6/contact_sheets.py
godot --audio-driver Dummy --rendering-method gl_compatibility --path godot/project -s ../art/buildings-v6/capture.gd -- --unit=SIEGE-RAM-01
```

Проверка iPhone 12 остаётся отдельной: сравнить город на одинаковых I–V сценариях, затем зрелый город из 26 объектов XI; вращение/масштабирование, строительство V→VI/X→XI, открытие меню, переход к карте и возврат. Результаты реального устройства и frame time этим пакетом не заявляются.
