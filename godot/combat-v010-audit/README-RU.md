## 3. Как это работает

* Флаг: `ProjectSettings` `drenovar/combat_v010/enabled` (по умолчанию `false`), командная строка `--combat-v010` / `--no-combat-v010`, в рантайме `CombatV010.set_enabled(bool)`.
* При включённом флаге боец создаётся, когда загружены и модель, и библиотека его типа (обе фоном; prewarm вместе с моделью при выходе отряда; бинарная библиотека — миллисекунды). Сразу после создания, до первого воспроизведения, presenter добавляет библиотеку в **собственный** AnimationPlayer импортированной модели под namespace `combat_v010`. Зверь — так же, библиотека грузится синхронно вместе с его GLB. С этого момента `landscape.gd` для актёра не вызывает `play_animation`/`additive_hit` — один владелец позы на всю жизнь актёра. Подключение библиотеки к уже играющему плееру отклоняется (в Godot 4.6.3 это давало нативный сбой — см. QA-RU §5). Включение флага посреди сессии действует на актёров, созданных после этого. Позицию/поворот корня по-прежнему задаёт существующий код; в клипах нет root motion (проверено).
* Ресурс библиотеки один на тип (общий кэш ResourceLoader), состояние воспроизведения — своё у каждого плеера (проверено в QA).
* Удар: `event.at` = контакт. Время клипа = `(elapsed − at + prepare)/1000`, `prepare` = contact из манифеста (ближний) или release + 260 мс полёта (дальний — совпадает с существующим `draw_arrow`). Поза — чистая функция серверного времени: повтор snapshot, rewind и late join не перезапускают замах. Клип играет сам и пересинхронизируется seek только при дрейфе >50 мс.
* Перекрывающиеся удары (события бойцов без модели «одалживаются» нарисованному того же типа): расписание `pick_strike` не обрезает подготовку и контакт — следующий удар показывается, только если его замах начинается ≥300 мс после предыдущего показанного контакта; иначе визуально пропускается (HP-бар, числа, исход — без изменений).
* Hit во время активного удара — только существующие contact FX (оверлей позвоночника отключён для v0.1.0, нет проверенной костной маски). Смерть — высший приоритет, последний кадр удерживается.
* Звери: Idle→idle/combat_idle, Roar→alert, Attack→attack_a (antler_charge → attack_b) с контактом 0.52 с в `event.at`, Hit→hit_front/left/right по направлению на ударившего бойца, Death→death (удержание; труп как раньше).
* ENG-04: перезарядка входит в 3.2-секундный attack, отдельный `reload` не играется. ENG-10: дротик (отдельный mesh `Javelin` в troops06) скрыт от release до перевооружения.

## 5. Откат

1. Мгновенно, без сборки: оставить `drenovar/combat_v010/enabled=false` (значение по умолчанию). В рантайме `CombatV010.set_enabled(false)` увеличивает generation, удаляет **только** библиотеку `combat_v010` с каждого плеера, сбрасывает `clip`, и со следующего кадра позу снова задаёт прежний код (проверено `qa_combat_v010.gd`).
2. Полный: `git revert <коммиты интеграции>` — затрагивает только `godot/project/combat_v010/`, `qa_combat_v010.gd`, `tests/combat_v010/`, `godot/combat-v010-audit/` и точечные правки `src/landscape.gd`, `project.godot` (секция `[drenovar]`), `export_presets.cfg` (include/exclude фильтры), `qa_hunt.gd`, `qa_world_hunt.gd`. Импортированные модели не удаляются, старая копия проекта не восстанавливается, миграций нет.
3. После отката проверить: `qa_hunt`, `qa_world_hunt`, `qa_battle_fx`, `qa_runtime` (городской и мировой бой, возвращение отряда). Сервер/БД не менялись — проверять там нечего.
