# DRENOVAR: переход из Combat Lab в обычную игру

Запрос владельца: после личной проверки анимаций на телефоне получить интерактивную игру с этими изменениями.

Причина режима просмотра: экспорт 1009 включал `custom_features="combat_lab"`, который выбирал `combat_lab.tscn` через feature override. Рабочий `main.tscn` уже использовал `CombatPresentation` для армии и животных. В 1011 отключён только экспортный выбор лаборатории, возвращён идентификатор установленного игрового клиента 1007, согласованы номера версии в проекте и Info.plist. Ресурсы моделей, текстуры и качество не уменьшены.

Дополнительная воспроизведённая ошибка: настоящее касание, закрывающее/заменяющее окно, удаляло кнопку раньше истечения 90 мс подсветки. GDScript сообщал `Lambda capture at index 0 was freed` ещё до проверки `is_instance_valid`. Таймер теперь держит WeakRef. Проверка кнопок включает удаление окна во время подсветки.

Проверки запускаются на Godot 4.6.3 / Linux; сервер — Node 24.22.1 с SQLite в памяти. `playable-server.mjs` получает путь к серверному checkout через `DRENOVAR_SERVER_ROOT`, слушает только 127.0.0.1, создаёт исключительно синтетические данные. Характеристики боя и серверные часы не меняются. Выданы только тестовые войска для сценария. Запись в реальную базу: 0.

Проверка `qa_playable_combat.gd`: обычная сцена, реальный HTTP и события touch через Input, состав 5 ENG-03 + 2 ENG-05, команда «Марш», серверный бой, читаемый результат, «Продолжить», возврат, сравнение гарнизона с потерями и повторный запуск с сохранённым входом. Значения состава выставляет сценарий в настоящих SpinBox; команды атаки, отправки и продолжения выполняются касанием, а не вызовом обработчика. Это автоматизация пользовательского пути, не приёмка физического iPhone.

`verify_playable_pack.gd` проверяет именно экспортный override главной сцены, отсутствие feature combat_lab, вход без автоматической регистрации, отсутствие сетевых запросов до входа, обе карты и полный прежний набор моделей. Проверку CI выполняют над PCK до упаковки IPA. SHA-256 и точный source commit публикуются рядом с IPA.

Версия общего сервера прочитана через `/__health`, `/api/auth/info`, `/api/v6/version`: `e5062aa292da895653c07dab50ce9b85a2a4ee11`, API 6, schema 6, `DRENOVAR-V6-C1.0`, существующие города, новые поселения отключены. Для проверки совместимости использован отдельный detached worktree ровно этого коммита. Ни ветки, ни production не слиты/обновлены.

Ограничения: серверные presentation-дополнения ветки `codex/combat-v6-20261116` не объявляются работающими на общем сервере. Полная история после холодного переподключения и короткий завершающий фрагмент мирового поражения требуют отдельной серверной публикации. Открытые вопросы исходного аудита (ранний подход по рельефу, отдельные оружейные клипы и измеренная приёмка iPhone) сохраняются в `godot/combat-audit/README-RU.md`. Сообщение владельца о визуальном одобрении 1009 не превращено в замеры производительности 1011.

Установка: обновление DRENOVAR 1005–1007 через SideStore с тем же Apple ID; приложение не удалять. Идентификатор `com.drenovar.game.v6test` совпадает с 1007. Если остался только Combat Lab, новая игровая установка потребует подключить существующий город через аккаунт; демонстрационная лаборатория не хранит вход в него.

## Результаты перед публикацией

- Экспортированный PCK: игровая сцена, аккаунт, город/мир, 21 модель войск/тарана, 162 здания — без ошибок; `after/local-exported-boot.log`.
- Полный интерактивный путь на этом PCK: 22/22; `after/result.json`. Сервер получил ровно 1 deploy с выбранными 5 лучниками и 2 конными разведчиками; `after/command-count.json`. Серверное время не ускорялось. Уцелевшие и потери сверены с `after/server-report.json`.
- Касания/перетаскивания/закрытие панели во время подсветки: 11/11. Зашифрованное сохранение входа и совместимость ключа: 11/11.
- Графический прогон на Linux llvmpipe/OpenGL: 21/22. Сбор, отправка, результат, продолжение и возврат подтверждены кадрами. В коротком бою графический прогон не зарегистрировал фазу `attack` (29 наблюдений актора за весь поход); в headless-прогоне на PCK она зарегистрирована. Графический прогон **не засчитан** как проверка анимаций/производительности. Кадры называются по авторитетному статусу сервера; они не доказывают конкретный кадр контакта. Звук воспроизводился в Dummy-драйвер, прослушивание не проверено.
- При завершении интеграционного стенда есть предупреждение ObjectDB о неосвобождённых экземплярах. Оно сохранено в журнале, не выдано за доказательство отсутствия утечек на iPhone. Прежние длительные проверки находятся в отчёте 1009.
- `before/interactive.log` сохраняет воспроизведение обращения к удалённой кнопке. Там же есть ошибочная ранняя проверка Dictionary с JSON-числами float против литералов int; её заменили сравнением количеств и общего размера отряда. Это исправление проверки, а не серверного состава.

Следующий этап владельца: установить 1011 поверх игрового клиента и повторить в основном городе путь «Атаковать → состав → Марш → результат → Продолжить». Заявление владельца об одобрении внешнего вида 1009 сохранено как обратная связь; оно не подменяет этот новый игровой прогон на телефоне.
