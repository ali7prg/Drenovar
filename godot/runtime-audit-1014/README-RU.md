# Игровая сборка 1014: зависание при отправке марша

Основа — `codex/combat-live-repair-20261116` (сборка 1013, `5807401`). Сервер не менялся: используется тот же опубликованный `0d201de`.

## Причина

`landscape.gd` → `engage_plan()` вызывал `CombatSlots.choose()` для каждого показанного бойца синхронно, внутри `present_armies()`. Для стрелков за линией ближнего боя каждый кандидат без прямого подхода запускал локальный A*: до 320 итераций с пересортировкой открытого списка и проверками коллизий по ходу движения. Таких кандидатов на бойца было до 16. В воспроизведённом случае один кадр длился 11,9–15 с на настольном CPU.

Ключ плана включал `encounter.position`. Сервер V6 (`timeline.mjs`) двигает живого зверя по 20-секундному патрулю при каждом опросе, поэтому план мог строиться заново на каждом ответе. Отсюда «вечное» зависание: кнопки не отвечают, ожидающие HTTP-запросы истекают («Нет связи»), а к концу зависания поход уже окончен и анимации не видно.

Та же текущая позиция зверя входила в `creature_lairs()` и в подпись города. Из-за этого каждый ответ сервера во время патруля заново проходил `present_city()`: участки, планирование стены и маркеры, около 4 мс на настольном CPU каждые 0,8 с.

## Исправление

- `combat_slots.gd`: планировщик отдаёт кадр каждые 2,5 мс (`pause()`). На одного бойца выполняется не больше одного A* (140 итераций, путь ≤ 24 м). Минимум открытого списка находится линейным проходом вместо сортировки. После расчёта физическое пространство освобождается (`release()`).
- `landscape.gd`: `engage_plan()` сразу возвращает расстановку по дугам и уточняет её в фоне (`refine_engage_plan`). Порядок прежний: сначала передняя пехота. С начала атаки или возвращения план фиксируется: нерассчитанный боец остаётся на дуге и не перескакивает. План пересчитывается, если цель сместилась больше чем на 3 м. `engage_sync = true` сохраняет прежний синхронный расчёт для инструментов QA.
- `creature_lairs()`: при наличии патруля используется вся линия патруля с шагом 2 м вместо текущей точки. Ограничение для стены остаётся таким же или строже, но не меняется между опросами.
- `combat_presentation.gd`: интервалы простоя (5 с) больше не попадают в буфер задержки боя, если в списке остались только вернувшиеся походы.
