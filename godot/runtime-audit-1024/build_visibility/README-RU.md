# Build 1024: новые здания на базе — сквозная проверка

Сообщение владельца: после «Построить» не видно, где идёт стройка; по окончании здания на базе нет,
а «Строить» пишет, что оно уже есть.

## Как проверяли

`godot/project/qa_build_e2e.gd`: клиент Godot против локальной копии боевого Worker V6
(`releaseWorker().fetch` из выложенного worker.mjs над SQLite в памяти, часы сервера управляются
тестом). Производственный сервер и данные игроков не затрагивались. Код сервера в репозиторий
не входит; как поднять такой сервер — в шапке скрипта.

Два поселения:
- **старого образца** — 16 зданий V на сетке `plot-N`, переведено в V6 собственной
  `planMigration` сервера (как у владельца);
- **королевство** — новое поселение V6, ратуша IV (два строителя).

Сценарий: «Строить» → карточка → участок (призрак и подсветка) → «Построить»; сразу второе здание
(второй строитель, `order2`); опросы состояния с 304; часы сервера за конец; опрос; затем третье
здание и заказ, который сервер отклоняет.

| До исправления (`d5814aea^`), задержка 700 мс | 107 проверок, **21 провал** | 111 проверок, **7 провалов** |
| С исправлением, без задержки | 110 / 0 | 108 / 0 |
| С исправлением, задержка 700 мс | 113 / 0 | 111 / 0 |
| С исправлением, отрисовка (lavapipe) | 110 / 0 | — |

До исправления в поселении старого образца: нет лесов, нет готового здания, нет таблички и
метки, участки предлагаются прямо на старых зданиях (v1-0 — на ратуше), а карточка пишет
«построено». В королевстве: леса появлялись только с ответом сервера и стояли в лесу (2–7
деревьев на участке).
