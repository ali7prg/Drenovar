# Серверный патч route-approach-v2 к DRENOVAR Server v92

**Статус: не развёрнут.** Production не обновлялся. Заменяет `route-approach-v1`: включает его
целиком (подход к зверю у постройки) и добавляет выход армии через ворота городской стены.
Причина ошибки «Нет безопасного пути к цели» и исправление v1 описаны в
`server-patches/route-approach-v1/README_RU.md`.

## Что добавляет v2

Стену вокруг двора (с ратуши II или после «Стен и ворот») рисует клиент. Сервер v92 её не хранит
и прокладывал путь сквозь неё. Теперь:

1. С городским походом (`march-preview` и приказ `deploy`) клиент присылает стену в том виде, в
   каком её рисует: `wall: {cx, cz, radii: [144 радиуса], gates: [[номер отсчёта, полуширина], …]}`
   (около 1 КБ).
2. Сервер разрешает шаг через линию стены только в проёме ворот. Поиск пути (тот же A*, те же
   проверки клеток `validCityPoint`) сам выводит отряд через ближайшие подходящие ворота и ведёт
   его снаружи вдоль стены. Если зверь внутри стены, отряд идёт по двору и стену не пересекает.
3. Стена только добавляет препятствия. Неправильная стена (не 144 радиуса, радиус вне 5–90 м,
   нет ворот или их больше 8, центр дальше 60 м) не учитывается. Если со стеной пути нет,
   берётся прежний маршрут. Поэтому приказ никогда не отклоняется из-за стены, а короче маршрут
   стать не может.
4. Без поля `wall` маршрут тот же, что в v1 (и для свободных клеток тот же, что в v92).

Сервер v92 без патча поле `wall` игнорирует (проверено: приказы проходят).

## Развёртывание

Как для v1 (`server-patches/route-approach-v1/README_RU.md`): сверить версию сайта с v92,
применить `route-approach-v2.patch` к чистой копии, запустить `route-approach.mjs`,
`route-wall.mjs` и `tools/run_original_tests.py`, собрать `hosting37`, проверить на отдельном
адресе с отдельной базой, затем production. Миграция не нужна. Откат — вернуть `navigation.mjs`
и `core.mjs` v92.
